======================================================================
 Recapitulatif des parametres -- wave_propagation (couplage
 elasto-acoustique HHO, formulations d'ordre 1 et d'ordre 2)
======================================================================

Le programme n'a que deux prototypes, choisis par le fichier d'entree
Lua (lu avec sol2, comme les autres applications diskpp) :

  ./wave_propagation mon_fichier.lua ["instructions lua" ...]

  formulation = "first_order"   -> HHOFirstOrder  (vitesse-contrainte /
                                   vitesse-pression, assembleur 4 champs)
  formulation = "second_order"  -> HHOSecondOrder (deplacement / potentiel
                                   des vitesses, assembleur 2 champs)

Les arguments qui suivent le fichier sont executes comme du Lua APRES
lui : ils surchargent le fichier sans le copier, par exemple

  ./wave_propagation first_order.lua "time.scheme = 'sdirk'; time.n_steps = 20"

Toute entree absente prend sa valeur par defaut ; une entree inconnue
(faute de frappe) est signalee par un WARNING au lancement. Le fichier
etant du Lua, on peut y utiliser variables, boucles et expressions.

Ou trouver les fichiers :
  - modeles annotes (toutes les cles, valeurs par defaut) :
      share/first_order.lua, share/second_order.lua
  - un exemple par couple formulation x schema, avec les reglages des
    articles : share/examples/*.lua
  - la campagne de verification des resultats de convergence de deux
    articles anterieurs (Burman-Duran-Ern 2022, Burman-Duran-Ern-Steins
    2021) : share/reproducibility/papers_Duran/ (voir son LISEZMOI.txt),
    recopiee dans <build>/apps/wave_propagation/reproducibility/papers_Duran
  - la campagne des cas tests de Mottier-Ern-Khot-Guillot (M2AN 2025)
    et Mottier-Ern-Guillot (CMAME 2025) : share/reproducibility/
    papers_Mottier/ (LISEZMOI.txt ; cles Lua correspondantes en section 6)
  - CMake recopie ces fichiers dans le dossier de build a la
    configuration : editer une copie sous un autre nom, ou la source.
  - l'ancien programme avec tous les prototypes de recherche :
      src/wave_propagation_legacy.cpp, compile seulement avec
      -DWAVE_PROPAGATION_LEGACY=ON (executable wave_propagation_legacy).

Code (src/, un dossier par theme) :
  parameters/      lua_parameters.hpp (struct wave_parameters,
                   load_wave_parameters), preprocessor.hpp (ancien
                   programme)
  mesh/            domain.hpp (types communs, maillages, milieux, zone

  physics/         materiaux, solutions analytiques, choix de la solution

  assembly/        assembleurs (base, quatre champs ordre 1, deux champs
                   ordre 2, trois champs elastique), assembly_tools.hpp

                   geometriques de cellules)
  solvers/         linear_solver.hpp (condensation statique, Pardiso),
                   parallel_sparse.hpp (matrice creuse des triplets en
                   parallele)
  time_schemes/    runge_kutta.hpp (ERK et SDIRK communs aux deux
                   formulations, interpolation de la force, polynome de
                   Taylor, increment RK4), lts.hpp (LTS-RK4 et LI-SDIRK

                   tableaux de Butcher, erk_coupling_hho_scheme,

1. Discretisation en espace -- table "space"
----------------------------------------------------------------------

  Cle               Valeurs                  Signification
  ------------------------------------------------------------------------
  k                 entier >= 0              degre des faces
  order             "equal" | "mixed"        cellules de degre k ou k+1
  stabilization     "least_squares" | "hho"  moindres carres (plain LS en
                                             ordre egal, Lehrenfeld-Schoberl
                                             en ordre mixte) ou stabilisation
                                             HHO avec terme de correction
  scaling           "1" | "1/h" | "graded"   poids de stabilisation O(1) ou
                    | "hybrid"               en 1/h ; "graded" : O(1) multiplie
                                             par max(1, h_max / h_T) ; "hybrid" :
                                             1/h dans les cellules plus petites
                                             que time.fine_size (0.75 h_max par
                                             defaut ; la zone implicite du
                                             li), O(1) ailleurs (ordre optimal sur
                                             maillages fortement gradues avec li ;
                                             limite de stabilite parabolique des
                                             cellules en 1/h : pas d'explicite)
  weight            nombre | "auto"          ordre 2 : poids gamma de la
                                             stabilisation ; "auto" =
                                             weight_factor * gamma*
  weight_factor     nombre                   ordre 2 (defaut 3)

Correspondance avec les articles :
  - MEG (CMAME), main.tex l.935-950 : tau^f = (rho c_p)^-1 h~^-alpha,
    tau^s = rho c_s h~^-alpha. alpha = 0 <-> scaling = "1",
    alpha = 1 <-> scaling = "1/h". Plain LS + alpha = 0 pour
    l'explicite, Lehrenfeld-Schoberl + alpha = 1 pour l'implicite.
    Code : elastoacoustic_four_fields_assembler, e_mixed_operator /
    a_mixed_operator (eta = 1.5 / 0.8, coefficients de reference),
    set_least_squares_stabilization, set_scaled_stabilization.
  - Steins-Ern-Jamond-Drui (M2AN 57, 2023) : poids gamma de la
    stabilisation, sigma* = partie face-face (bloc-diagonale) de la
    stabilisation, gamma* = poids critique du splitting calcule
    cellule par cellule sans conditions aux limites (Lemme 4.3,
    Tableau 1), reglage optimal gamma dans [3 gamma*, 5 gamma*] en
    ordre mixte (Sec. 5.1.2).
    Code : elastoacoustic_two_fields_assembler, e_laplacian_operator /
    a_laplacian_operator (2 mu (R + gamma S) + lambda D,
    (R + gamma S) / rho), set_stabilization_weight,
    set_stabilization_scaling, face_stabilization_mass (sigma*),
    HHOSecondOrder.hpp problem::critical_weight (gamma*).

Contraintes verifiees au lancement :
  - stabilization = "hho" impose scaling = "1/h" (la stabilisation HHO
    de diskpp est toujours en 1/h).
  - ordre 1 : erk, lts et li eliminent les faces avec le bloc face-face
    bloc-diagonal des moindres carres -> stabilization = "least_squares".


----------------------------------------------------------------------
2. Faces algebriques de l'ordre 2 -- table "faces"
----------------------------------------------------------------------

Schemas explicites (erk, lts) et li uniquement ; sdirk resout les faces
dans ses systemes d'etage.

  solver           "splitting" : D a^{m+1} = r - (K_aa - D) a^m,
                   D = gamma sigma* (Steins et al., Sec. 4), totalement
                   explicite, contraction gamma*/gamma
                   "direct" : factorisation creuse de K_aa
  tolerance        increment relatif d'arret du splitting (1e-14)
  max_iterations   (20000)
  localize         (false) lts et mlts avec F = 0 (pas de source,
                   donnees de Dirichlet nulles) : evaluations locales.
                   B P z (pas fins) et B Q a_i (coefficients de Taylor)
                   resolvent les faces depuis zero sur les seules faces
                   atteintes (un anneau de plus par iteration : memes
                   valeurs que l'iteration sur toutes les faces depuis
                   zero) ; B y, B^2 y, B^3 y ne servent que sur la bande
                   du niveau et sont tronques a la bande + 3R, 2R, R
                   anneaux de cellules, R = log(tol (1 - rho)) / log rho
                   + localize_margin, rho = rayon spectral du splitting
                   (erreur de troncature de l'ordre de tolerance). F
                   n'est jamais assemble. Resultats egaux a ceux de
                   localize = false a la tolerance des faces pres. Sans
                   effet sur erk, sdirk, li, newmark.
  localize_margin  anneaux ajoutes a R (2)
  projected        (false) lts et mlts : condensation projetee. Les
                   sous-pas du niveau l >= 1 utilisent l'operateur B~_l
                   des niveaux >= l dont les faces ne sont resolues que
                   sur leurs cellules (+ projected_rings anneaux), nulles
                   au-dela : probleme HHO local, bloc des faces factorise
                   une fois (LDL^T). Decoupage exact B = B~_{L-1} +
                   somme (B~_l - B~_{l+1}), B~_0 = B : le niveau l fige
                   (B~_l - B~_{l+1}) a_i, a_i derivees de z' = B~_l z +
                   W(tau) ; seul le niveau 0 evalue B sur tout le
                   maillage (4 fois par pas grossier). Schema different
                   de projected = false (memes ordre et stabilite :
                   limite CFL des cellules grossieres sans recouvrement
                   supplementaire, verifie jusqu'a p = 16). mlts : F = 0
                   seulement.
  projected_rings  anneaux de cellules ajoutes aux faces resolues (2 ;
                   0 suffit et sert dans le preprint)

En ordre egal avec la stabilisation "hho", alpha_solide =
lambda_max(S_aa, sigma*_aa) - 1 vaut 1.63 / 0.91 / 1.79 pour
k = 1 / 2 / 3 : le splitting ne peut pas converger pour k = 1, 3
(Lemme 4.4) -> utiliser l'ordre mixte ou solver = "direct".

3. Schema en temps -- table "time", table "solver"
----------------------------------------------------------------------

  scheme       "erk"   : ERK(s), s = stages = 1..4
               "sdirk" : SDIRK(s, s+1), s = 1..3 (une factorisation)
               "newmark" : Newmark(beta, gamma), formulation d'ordre 2
                         uniquement, sur toutes les inconnues (cellules
                         et faces) ; newmark_beta = 1/4, newmark_gamma =
                         1/2 par defaut (energie exactement conservee)
               "lts"   : LTS-RK4 a deux niveaux (coefficients de Taylor
                         grossiers, sous-pas RK4 dans la zone fine)
               "li"    : LI-SDIRK(4,3), ERK4 grossier + SDIRK(3,4) fin
               "mlts"  : LTS-RK4 multiniveau (algorithme 4 du preprint
                         LTS_HHO), deux formulations (ordre 1 : mode
                         rapide de solver.matrix_free ou matrices ;
                         ordre 2 : lts.hpp sur second_order_system) :
                         niveaux tires des tailles de cellules, chaque
                         niveau calcule ses coefficients de Taylor sur sa
                         fenetre, le plus fin fait les pas RK4
  stages       0 = 4 pour erk, 3 pour sdirk
  final_time   temps final
  n_steps      pas de temps sur le premier maillage de l'etude
               (dt = final_time / n_steps), double a chaque niveau d'une
               etude "space"
  substeps     lts : sous-pas fins (0 = round(h_max / h_min))
  fine_size    lts, li : cellules plus petites que fine_size (+ une couche
               de voisines par sommet) = zone fine ; 0 = 0.75 h_max
               (tout le maillage s'il est uniforme) ; space.scaling =
               "hybrid" : stabilisation 1/h sous ce seuil (0.75 h_max
               sinon)
  fine_layers  lts, li : couches de voisines par sommet ajoutees a la zone
               fine (recouvrement ; defaut 1)
  fine_measure lts, li : taille d'une cellule comparee a fine_size :
               "diameter" (defaut) ou "width" (largeur : plus petite
               hauteur du polygone, min sur les aretes de la distance
               maximale des sommets a la droite de l'arete ; le pas stable
               d'une cellule suit sa largeur, pas son diametre : cellules
               minces, morceaux de cellules coupees)
  level_ratio  mlts : rapport r >= 2 entre les pas de deux niveaux
               consecutifs ; cellule T au niveau
               ceil(log(h_max / h_T) / log r), faces au niveau de leur
               cellule la plus fine (defaut 2)
  level_ratios mlts : rapports p_0, p_1, ... par niveau (du plus grossier
               au plus fin, le dernier repete), au lieu de level_ratio ;
               cellule T au premier niveau l tel que p_0 ... p_{l-1} >=
               h_max / h_T. Ex. {2, 2, 2, 8} : niveau le plus fin
               couvrant trois tailles de cellules (section 7)
  level_measure mlts : "h" (defaut, x_T = h_max / h_T) ou "h/c"
               (x_T = max(h / c) / (h_T / c_T), c la vitesse P de la
               cellule : milieux heterogenes, le CFL d'une cellule
               suit h_T / c_T) ; le LTS a deux niveaux en milieu
               heterogene : mlts avec level_ratios = {p}
  level_size   mlts : taille d'une cellule dans la mesure des niveaux :
               diametre (defaut), 4 |T| / |dT| ("area") ou largeur
               ("width", voir fine_measure : recommande pour les cellules
               minces, morceaux de cellules decoupees le long d'une
               interface ajustee, dont le diametre surestime la taille)
  level_tolerance mlts : la mesure x_T est divisee par 1 + level_tolerance
               avant le choix du niveau (defaut 0) : des milieux de
               vitesses voisines (tissus mous 1.50 / 1.55) restent au meme
               niveau ; le pas grossier diminue d'au plus ce facteur
  li_coupling  li (mode rapide) : "taylor" (defaut) ou "stage" : valeurs
               grossieres des etages implicites = valeurs d'etage du
               tableau SDIRK, y_n + dt sum_l a_il Y'(c_l dt), au lieu du
               polynome de Taylor en t_n + c_i dt : supprime la reduction
               d'ordre (ordre 2 -> 4 avec dt ~ h_max) ; mise a jour finale
               inchangee (conditions d'ordre de SDIRK(3,4))
  li_condensation li (mode rapide) : true = condensation statique du
               systeme fin (inconnues de cellules eliminees cellule par
               cellule, LU du complement de Schur sur les faces fines :
               systeme 4 fois plus petit, 3 a 7 fois plus rapide)
  li_system    li (mode rapide) : "dynamic" (defaut) ou "constraint" :
               faces internes a la zone fine donnees par leur
               condensation statique u_F = G u_T dans les systemes
               d'etage, pentes (U_i - R_i) / (gamma dt) ; meme schema en
               arithmetique exacte, systeme bien conditionne quand la zone
               fine est tres raide (maillages fortement gradues,
               stabilisation 1/h : le mode "dynamic" donne des NaN)
  overlap      mlts : couches de cellules voisines (par sommet) ajoutees
               a chaque niveau depuis le niveau grossier voisin (defaut 1)
  overlaps     mlts : {o_1, o_2, ...} couches annexees par les niveaux 1,
               2, ... (le dernier repete), au lieu de overlap
  mlts_reuse   mlts (mode rapide) : true = coefficients propres d'un niveau
               tires de la chaine a_{i+1} = B a_i sur ses inconnues
               profondes (cellules du niveau dont toutes les faces sont du
               niveau, faces dont toutes les cellules sont profondes),
               produits masques sur la seule couche de bord, plus un
               produit B a_3 : environ 4 produits par inconnue au lieu de 7
               sur un niveau epais (le plus grossier) ; meme schema,
               resultats egaux aux arrondis pres ; defaut false
  mlts_refresh mlts : "window" (defaut, algorithme 4 : coefficients d'un
               niveau calcules une fois par fenetre du niveau) ou
               "substep" (recalcules a chaque sous-fenetre du niveau
               suivant, variante des prototypes : r fois plus de
               coefficients, erreur en temps 16 fois plus petite a dt
               egal pour r = 2, meme limite de stabilite). Un seul
               niveau : ERK4.
  newmark_beta, newmark_gamma  parametres de Newmark (beta > 0, gamma >= 1/2)
  solver.static_condensation   sdirk d'ordre 1, newmark : condensation
                               statique des cellules
  solver.matrix_free           ordre 1, mode rapide (section 7) : erk, lts,
                               li, mlts et etude "cfl" sur l'operateur explicite
                               sans matrice globale ; sdirk : produits
                               paralleles, Pardiso sans raffinement
                               iteratif ; assemblage parallele, donnees de
                               F(t) gardees ; defaut false
  solver.matrix_free_tolerance blocs locaux partages a cette tolerance
                               relative pres (defaut 1e-10 ; 0 : egalite
                               bit a bit, < 0 : un bloc par cellule)
  solver.matrix_free_batch     cellules par produit de blocs (defaut 64)
  solver.parallel_threshold    lts, mlts, li (mode rapide) : produits sur
                               un ensemble de plus de parallel_threshold
                               inconnues sur les fils, les autres sur un
                               seul fil (defaut 20000)
  solver.matrix_free_precision "single" : blocs de calcul des cellules en
                               simple precision (maillages non
                               structures ; section 7) ; defaut "double"
  solver.fast                  mode rapide de tous les schemas des deux
                               formulations (section 7) ; ordre 1 : vaut
                               matrix_free = true ; defaut false

Ordre 2 : variable auxiliaire v = u_T' (vitesse des cellules) ; les
inconnues d'interface (acoustique + composante normale elastique, par
QR local du bloc de couplage) sont dynamiques, les autres faces
algebriques. Les schemas explicites affichent omega_max (iteration de
puissance) et un WARNING si dt depasse leur limite de stabilite.

Code : un seul ERK et un seul SDIRK pour les deux formulations
(src/time_schemes/runge_kutta.hpp : chaque formulation donne sa pente ou
sa resolution d'etage), un seul LTS-RK4 et un seul LI-SDIRK
(src/time_schemes/lts.hpp : coefficients de Taylor de la zone grossiere,
sous-pas RK4, etages LI) sur l'operateur de chaque formulation :
erk_coupling_hho_scheme::lts_operator (ordre 1 ; les routines
erk_weight_LTS_coarse / _coarse_global / _fine et dirk_weight_LTS_fine
des prototypes y renvoient aussi) et lts_operator de
src/second_order/time_schemes.hpp (ordre 2, sur second_order_system :
eval, solve_faces, factorize_stage / stage_solve ; une amorce des faces
algebriques par evaluation). L'operateur fixe deux conventions :
  - masquage de la force : l'ordre 1 masque la force avant l'operateur
    (w_i = f((I-P) F_i, (I-P) a_i), faces recalculees depuis les
    cellules), l'ordre 2 apres ((I-P) g(F_i), g(F) = f(F, 0)) ;
  - pente des etages LI : l'ordre 1 la recalcule par l'operateur
    (k = f(P F, P Z) + w), l'ordre 2 la tire de la resolution
    (k = (Z - R) / h).
Seul le masquage de la force change le schema (pres de la frontiere de
la zone fine, quand il y a une source) ; les deux pentes LI sont
algebriquement egales (Z = R + h k), elles ne different que par les
arrondis. Versions _mf de l'ordre 1 : mf_erk_operator.

4. Maillage, probleme, etude, sorties
----------------------------------------------------------------------

  mesh.type               "cartesian" (defaut) ou "fvca5" (fichiers au
                          format du benchmark FVCA5, par exemple les
                          maillages polygonaux de diskpp,
                          refactor_old_diskpp_code/meshes/2D_hex) ;
                          mesh.files = {"f1", "f2", ...} : le niveau l lit
                          mesh.files[l] (l >= 1)
  mesh.x, mesh.y          rectangle ; en milieu couple, l'interface x = 0
                          doit etre une ligne du maillage grossier
  mesh.nx, mesh.ny        cellules du maillage grossier
  mesh.level              raffinements uniformes
  mesh.refine_points      points {{x, y}, ...} : les cellules a moins
                          d'une taille de maille sont raffinees ...
  mesh.refine_levels      ... ce nombre de fois (noeuds pendants) : zone
                          fine de lts et li (niveau >= 1 sinon la zone
                          couvre tout le maillage)
  mesh.refine_box         {x0, x1, y0, y1} : les cellules dont le
                          barycentre est dans la boite sont raffinees
                          refine_levels fois, avec une transition
                          graduee (un niveau de moins par couronne,
                          refine_with_protection des prototypes de
                          stabilite) ; au lieu de refine_points
  mesh.type "polygons"    polygones etiquetes (mesh/domain.hpp), par
                          exemple ceux de mesh_generation/brain_mri
  problem.medium          "coupled" (defaut : solide x < 0, fluide x > 0,
                          interface x = 0), "acoustic" ou "elastic" (un
                          seul milieu)
  problem.solution        milieu couple : "interface_coupling" (traces
                          non nulles sur l'interface, teste le couplage)
                          ou "non_polynomial" (nulle avec son gradient sur
                          l'interface) ; milieu acoustique (Burman-Duran-
                          Ern 2022) : "acoustic_quadratic_in_time" (60),
                          "acoustic_quadratic_in_space" (61),
                          "acoustic_non_polynomial" (62) ; milieu
                          elastique (Burman-Duran-Ern-Steins 2021) :
                          "elastic_quadratic_in_time" (78),
                          "elastic_quadratic_in_space" (79),
                          "elastic_non_polynomial" (80). Materiaux :
                          solide rho = 1, vp = sqrt(3), vs = 1 ; fluide
                          rho = 1, vp = 1 (scal_vec_analytic_functions)
  study.type              "run" (un calcul), "space" (niveaux
                          mesh.level .. last_level), "time" (n_steps 2^i,
                          i < time_levels, maillage mesh.level)
  study.refine_dt         etude "space" : dt divise par 2 avec h (true,
                          defaut) ou fixe (false)
  study.reference         etude "time" : "numerical" (defaut ; contre une
                          reference reference_factor fois plus fine du meme
                          schema, normes M et energie) ou "exact" (erreurs
                          contre la solution exacte seulement)
  output.file             tableau de convergence ("" = nom construit a
                          partir des parametres)
  output.table            les memes erreurs sans les ordres, une ligne par
                          niveau, colonnes nommees dans un en-tete "#"
                          ("" = output.file avec l'extension .dat) : lu
                          par les scripts de la campagne
  output.energy           newmark : historique de l'energie discrete (69)
                          de Burman-Duran-Ern-Steins 2021,
                          1/2 v^T M v + 1/2 somme_T u_T^T A_T u_T, les
                          faces de Dirichlet portant les donnees au temps t
                          (<table>_energy.dat) ; conservee exactement
                          (beta = 1/4, gamma = 1/2) sans source et avec
                          des donnees de Dirichlet constantes en temps


----------------------------------------------------------------------
5. Reglages des articles et pieges connus
----------------------------------------------------------------------

  Ordre 1, explicite (erk, lts, li) : order "equal", "least_squares",
           scaling "1" (un facteur 1/h degraderait la CFL).
  Ordre 1, implicite (sdirk) : order "mixed", "least_squares"
           (Lehrenfeld-Schoberl), scaling "1/h".
  Ordre 2, explicite (erk, lts, li) : reglage optimal de Steins :
           order "mixed", "least_squares", scaling "1/h", weight
           "auto", weight_factor dans [3, 5], faces.solver "splitting".
  Ordre 2, implicite (sdirk) : order "mixed", "least_squares",
           scaling "1/h", weight 1.

  - SDIRK (ordre d'etage 1) avec des donnees de Dirichlet non
    homogenes dependant du temps et un grand pas : reduction d'ordre
    (ordre 2 a 2.5 au lieu de s+1) ; disparait quand dt diminue ou
    avec des donnees homogenes. Ce n'est pas un defaut du code.
  - Ordre 2 : un seul niveau de raffinement local (h/2) ne change
    presque pas omega_max ; lts et li ne sont utiles qu'avec
    refine_levels >= 2.
  - Etude "time" d'un schema implicite a maillage fixe : tant que
    dt omega_max >> 1, les hautes frequences ne sont pas resolues et la
    distance a la reference plafonne (surtout en norme d'energie).

6. Ordre 1 : cles ajoutees pour les campagnes papers_Mottier

  space.weight_elastic     et elastique (defaut 0.8 / 1.5, ou space.weight)
  space.stabilization_size h du poids en 1/h : "diskpp" (defaut), "cell"
                           (diametre de la cellule) ou "face"
  space.elastic_formulation "velocity_stress" (defaut) ou "three_fields"
                           (elastique seul, Burman-Duran-Ern-Steins 2021)
  space.interface_quadrature  "exact" (defaut : regle de degre 2k pour le
                           couplage) ou "legacy" (regle de degre k du code
                           des articles, couplage de rang deficient pour
                           k >= 1) : seulement pour comparer aux resultats
                           publies
  solver.iterative         sdirk : BiCGSTAB + ILU au lieu de Pardiso ;

Ordre 1. solver.matrix_free = true remplace, pour erk, lts, li et l'etude "cfl",

  Operateur   k_c = Mc^-1 (F_c - Kcc y_c - Kcf y_f), k_f = -Sff^-1 Kfc k_c
              (stabilisation moindres carres : Sff diagonal par blocs).
              Chaque cellule K garde D = -Mc^-1 Kcc, E = -Mc^-1 Kcf,
              M = Mc^-1 et H (colonnes de K dans -Sff^-1 Kfc de ses
              faces) : k_K = D y_K + E y_f(J_K) (+ M F_K), puis ses
              contributions H k_K a ses faces ; k_f = somme des
              contributions des deux cellules de la face.
  Partage     les blocs identiques (maillages structures : meme
              materiau, meme taille, meme configuration de bord) sont
              stockes une fois : 8892 cellules k = 3 -> 2 blocs D, 19 E.
              Comparaison dans les unites de la norme d'energie
              (inconnues de cellule ponderees par la racine de la
              diagonale de la masse, de face par la taille de leur
              trace) : contraintes et vitesses different de 7 ordres de
              grandeur, une comparaison relative au maximum du bloc ou
              de la ligne serait fausse. Les entrees sous la tolerance
              (arrondi de l'assemblage, environ 1e-11) sont supprimees :
              il reste 13 a 19 % des entrees, gardees en blocs creux.
  Calcul      cellules par lots de meme bloc (une colonne par cellule) :
              une entree de bloc = un AXPY vectorise sur les cellules du
              lot ; OpenMP sur les lots puis sur les faces ; etapes ERK
              (combinaisons, mise a jour) fusionnees dans le noyau.
  LTS, LI     w_i = B_{F_i}((I-P) a_i, (I-P) F_i) calcule comme
              a_{i+1} - B_{F_i}(P a_i, P F_i) : quatre produits sur tout
              le maillage par pas (comme une etape ERK4), corrections et
              sous-pas fins (lts) ou etages implicites (li, systeme
              restreint aux inconnues fines, LU creux) sur la seule

              RK4 / SDIRK(3,4) du polynome de Taylor en forme close.
  Assemblage  avec solver.matrix_free : matrices locales calculees en
              parallele et dispersees dans l'ordre du calcul serie (memes

              stockes ; pas d'erk_coupling_hho_scheme (memoire).
  Fils        OMP_NUM_THREADS <= nombre de coeurs physiques (12 ici) :

Reproductibilite au bit pres. Avec -ffast-math (OPT_AGGRESSIVE_FP = ON,
defaut de diskpp), le compilateur peut regrouper autrement les sommes
des calculs locaux (quadratures) des que le code qui les entoure change,
meme sans que ce code soit execute : le chemin par defaut (sans
solver.matrix_free) fait les memes operations qu'avant, mais ses
resultats peuvent differer du dernier bit de ceux de l'executable des
campagnes. Mesure : tableaux d'erreurs des exemples identiques ;
energie 4e-16 a 5e-16 en relatif (Ricker ERK4, MEKG Fig. 13 SDIRK),
capteurs 1e-14 a 1e-10 sur des composantes presque nulles. Pardiso
multifil n'est pas reproductible d'un calcul a l'autre (dernier bit),
le mode rapide l'est (memes resultats quel que soit le nombre de fils).
Une reproductibilite stable d'une version du code a l'autre demande
OPT_AGGRESSIVE_FP = OFF (arithmetique IEEE stricte ; tous les resultats
changent alors une fois du dernier bit).
